# Godot Engine教育ゲーム - メインシーン表示計画書

## プロジェクト概要

Godot Engineを学ぶための教育ゲームにおいて、以下の要件を満たす実装を行う：

- **フロントエンド**: 教育ゲームのメインシーンを通常のGodotゲームとして表示
- **バックエンド**: 背後でGodot Engineを非表示で実行し、学習者の操作対象とする

## プラットフォーム対応状況

| **Windows** | ✅ 可能 | ✅ 可能 | ✅ 可能 | アプローチ1 |

## 技術的アプローチ

Godotのコードベース調査により、以下の3つの実装アプローチが確認された。

### アプローチ1: ヘッドレスモードの別プロセス実行 ⭐デスクトップ推奨

**概要:**
- メインプロセス: 教育ゲームのGUI（通常表示）
- サブプロセス: `--headless` フラグで起動した非表示Godotインスタンス
- プロセス間通信: `--remote-debug` によるデバッガプロトコル

**メリット:**
- 完全に独立したGodotインスタンス
- クラッシュの分離（一方が落ちても他方は継続）
- 既存のエディタ実行メカニズムを活用可能

**デメリット:**
- プロセス間通信の実装が必要
- リソース使用量が比較的多い

**技術的根拠:**
- `main/main.cpp:1399-1410` - ヘッドレスモード実装
- `editor/run/editor_run.cpp:49-190` - プロセス起動フロー
- `servers/display_server_headless.h` - ヘッドレスDisplayServer

### アプローチ2: SubViewportによる埋め込み実行 ⭐Web/モバイル推奨

**概要:**
- 単一プロセス内で複数の`SubViewport`を使用
- 教育ゲームシーン: メインウィンドウに表示
- 学習対象シーン: `SubViewport`で非表示実行（`UPDATE_ALWAYS`モード）

**対応プラットフォーム:**
- ✅ Web (Emscripten)
- ✅ Android
- ✅ iOS
- ⚠️ Nintendo Switch（Godot非対応だが、理論上は可能）

**メリット:**
- 単一プロセスでシンプル
- プロセス間通信不要
- リソース効率が良い
- **Webブラウザで動作可能**（プロセス起動制限を回避）
- クロスプラットフォーム対応

**デメリット:**
- 同じSceneTree内での実行のため、グローバル状態の競合リスク
- クラッシュ時に全体が停止
- ノードパスやシングルトンの命名衝突に注意が必要

**技術的根拠:**
- [scene/main/viewport.h:859-914](scene/main/viewport.h#L859-L914) - SubViewport定義
- [scene/main/viewport.cpp:5463-5483](scene/main/viewport.cpp#L5463-L5483) - 更新モード設定
- [scene/gui/subviewport_container.h](scene/gui/subviewport_container.h) - UI埋め込み
- [platform/web/display_server_web.cpp:1298-1302](platform/web/display_server_web.cpp#L1298-L1302) - Webは単一ウィンドウのみサポート

### アプローチ3: macOS埋め込みプロセス（プラットフォーム限定）

**概要:**
- エディタのゲームビュー機能を応用
- `--embedded` フラグで別プロセスを起動
- macOSネイティブのウィンドウ埋め込み機能を使用

**メリット:**
- エディタと同じ仕組みを利用
- プロセス分離とUI統合を両立

**デメリット:**
- macOSのみ対応
- 実装が複雑（プラットフォーム固有コード）

**技術的根拠:**
- `platform/macos/display_server_embedded.h` - 埋め込みDisplayServer
- `platform/macos/editor/embedded_process_macos.h` - プロセス埋め込み実装
- `editor/run/game_view_plugin.h` - ゲームビュープラグイン

```gdscript
# education_game_controller.gd
extends Node

var background_engine_pid: int = 0
var debug_connection: StreamPeerTCP = null

func start_background_engine(scene_path: String) -> Error:
    # エンジンバイナリパスを取得
    var engine_path = OS.get_executable_path()
    var project_path = ProjectSettings.globalize_path("res://")

    # 起動引数を構築
    var args = [
        "--path", project_path,
        "--headless",                    # ヘッドレスモード
        "--remote-debug", "tcp://127.0.0.1:6007",  # デバッグ通信
        scene_path                        # 実行シーン
    ]

    # プロセス起動
    background_engine_pid = OS.create_process(engine_path, args)

    if background_engine_pid == -1:
        push_error("Failed to start background engine")
        return ERR_CANT_CREATE

    print("Background engine started: PID ", background_engine_pid)

    # デバッガ接続を確立
    await get_tree().create_timer(1.0).timeout  # 起動待機
    _connect_to_debugger()

    return OK

func _connect_to_debugger() -> void:
    debug_connection = StreamPeerTCP.new()
    var err = debug_connection.connect_to_host("127.0.0.1", 6007)
    if err != OK:
        push_error("Failed to connect to background engine debugger")
        return
    print("Connected to background engine debugger")

func stop_background_engine() -> void:
    if background_engine_pid > 0:
        OS.kill(background_engine_pid)
        background_engine_pid = 0
    if debug_connection:
        debug_connection.disconnect_from_host()
        debug_connection = null

func _exit_tree() -> void:
    stop_background_engine()
```

### Phase 2: プロセス間通信（IPC）実装

**2.1 デバッガプロトコルを使用した通信**

参考: `editor/debugger/editor_debugger_node.cpp`

```gdscript
# ipc_bridge.gd
extends Node

signal command_executed(result)
signal state_changed(new_state)

var connection: StreamPeerTCP = null
var message_queue: Array = []

func send_command(command: String, params: Dictionary = {}) -> void:
    if not connection or connection.get_status() != StreamPeerTCP.STATUS_CONNECTED:
        push_error("Not connected to background engine")
        return

    # メッセージをパケット化
    var message = {
        "type": "command",
        "command": command,
        "params": params,
        "timestamp": Time.get_unix_time_from_system()
    }

    var json = JSON.stringify(message)
    var packet = json.to_utf8_buffer()

    # パケット送信
    connection.put_32(packet.size())
    connection.put_data(packet)

func _process(_delta: float) -> void:
    if not connection:
        return

    # メッセージ受信処理
    if connection.get_available_bytes() >= 4:
        var size = connection.get_32()
        if connection.get_available_bytes() >= size:
            var packet = connection.get_data(size)
            if packet[0] == OK:
                var json = packet[1].get_string_from_utf8()
                var message = JSON.parse_string(json)
                _handle_message(message)

func _handle_message(message: Dictionary) -> void:
    match message.get("type", ""):
        "result":
            command_executed.emit(message.get("data", {}))
        "state":
            state_changed.emit(message.get("data", {}))
```

**2.2 学習対象エンジン側の受信処理**

```gdscript
# background_engine_listener.gd
# バックグラウンドエンジン側で実行されるスクリプト
extends Node

var server: TCPServer = null
var client: StreamPeerTCP = null

func _ready() -> void:
    # デバッグサーバー起動
    server = TCPServer.new()
    server.listen(6007, "127.0.0.1")
    print("Background engine listening on port 6007")

func _process(_delta: float) -> void:
    # 接続待機
    if not client and server.is_connection_available():
        client = server.take_connection()
        print("Client connected")

    # コマンド受信
    if client and client.get_available_bytes() >= 4:
        var size = client.get_32()
        if client.get_available_bytes() >= size:
            var packet = client.get_data(size)
            if packet[0] == OK:
                var json = packet[1].get_string_from_utf8()
                var message = JSON.parse_string(json)
                _execute_command(message)

func _execute_command(message: Dictionary) -> void:
    var command = message.get("command", "")
    var params = message.get("params", {})

    match command:
        "get_node_property":
            var node_path = NodePath(params.get("path", ""))
            var property = params.get("property", "")
            var node = get_node_or_null(node_path)
            if node:
                var value = node.get(property)
                _send_response({"value": value})

        "set_node_property":
            var node_path = NodePath(params.get("path", ""))
            var property = params.get("property", "")
            var value = params.get("value")
            var node = get_node_or_null(node_path)
            if node:
                node.set(property, value)
                _send_response({"success": true})

        "call_method":
            var node_path = NodePath(params.get("path", ""))
            var method = params.get("method", "")
            var args = params.get("args", [])
            var node = get_node_or_null(node_path)
            if node and node.has_method(method):
                var result = node.callv(method, args)
                _send_response({"result": result})

func _send_response(data: Dictionary) -> void:
    if not client:
        return

    var response = {
        "type": "result",
        "data": data,
        "timestamp": Time.get_unix_time_from_system()
    }

    var json = JSON.stringify(response)
    var packet = json.to_utf8_buffer()

    client.put_32(packet.size())
    client.put_data(packet)
```

### Phase 3: 状態同期機能

**3.1 状態同期マネージャー**

```gdscript
# state_sync_manager.gd
extends Node

@export var sync_interval: float = 0.1  # 100msごとに同期

var ipc_bridge: Node = null
var synced_properties: Dictionary = {}
var timer: Timer = null

func _ready() -> void:
    timer = Timer.new()
    timer.wait_time = sync_interval
    timer.timeout.connect(_sync_state)
    add_child(timer)
    timer.start()

func register_property(node_path: NodePath, property: String, callback: Callable) -> void:
    var key = str(node_path) + ":" + property
    synced_properties[key] = {
        "node_path": node_path,
        "property": property,
        "callback": callback
    }

func _sync_state() -> void:
    for key in synced_properties:
        var sync_data = synced_properties[key]
        ipc_bridge.send_command("get_node_property", {
            "path": str(sync_data.node_path),
            "property": sync_data.property
        })

func _on_command_executed(result: Dictionary) -> void:
    # コールバック呼び出し
    for key in synced_properties:
        var sync_data = synced_properties[key]
        if result.has("value"):
            sync_data.callback.call(result.value)
```

```gdscript
# property_inspector.gd
extends VBoxContainer

var current_node_path: NodePath = NodePath()

    current_node_path = node_path

    # 型に応じたエディタを作成
```

**2.2 プロパティインスペクタ（簡易版）**

```gdscript
# property_inspector.gd
extends VBoxContainer

var current_node: Node = null
var learning_viewport: SubViewport = null

func show_node_properties(node_path: NodePath) -> void:
    # ビューポート内のノードを取得
    var root = learning_viewport.get_child(0)
    if not root:
        return

    current_node = root.get_node_or_null(node_path)
    if not current_node:
        push_error("Node not found: " + str(node_path))
        return

    # UI をクリア
    for child in get_children():
        child.queue_free()

    # プロパティリストを取得
    var properties = current_node.get_property_list()

    for prop in properties:
        # エディタに表示されるプロパティのみ
        if prop.usage & PROPERTY_USAGE_EDITOR:
            _add_property_editor(prop)

func _add_property_editor(prop: Dictionary) -> void:
    var hbox = HBoxContainer.new()

    var label = Label.new()
    label.text = prop.name
    label.custom_minimum_size.x = 150
    hbox.add_child(label)

    var editor = _create_editor_for_type(prop.type, prop.name)
    hbox.add_child(editor)

    add_child(hbox)

func _create_editor_for_type(type: int, property_name: String) -> Control:
    match type:
        TYPE_BOOL:
            var checkbox = CheckBox.new()
            checkbox.button_pressed = current_node.get(property_name)
            checkbox.toggled.connect(func(value):
                current_node.set(property_name, value)
            )
            return checkbox

        TYPE_INT:
            var spinbox = SpinBox.new()
            spinbox.value = current_node.get(property_name)
            spinbox.value_changed.connect(func(value):
                current_node.set(property_name, int(value))
            )
            return spinbox

        TYPE_FLOAT:
            var spinbox = SpinBox.new()
            spinbox.step = 0.01
            spinbox.value = current_node.get(property_name)
            spinbox.value_changed.connect(func(value):
                current_node.set(property_name, value)
            )
            return spinbox

        TYPE_STRING:
            var lineedit = LineEdit.new()
            lineedit.text = current_node.get(property_name)
            lineedit.text_changed.connect(func(value):
                current_node.set(property_name, value)
            )
            return lineedit

        TYPE_VECTOR2:
            var vector2_editor = HBoxContainer.new()
            var x_spin = SpinBox.new()
            var y_spin = SpinBox.new()
            x_spin.step = 0.01
            y_spin.step = 0.01
            var vec = current_node.get(property_name)
            x_spin.value = vec.x
            y_spin.value = vec.y
            x_spin.value_changed.connect(func(_v):
                current_node.set(property_name, Vector2(x_spin.value, y_spin.value))
            )
            y_spin.value_changed.connect(func(_v):
                current_node.set(property_name, Vector2(x_spin.value, y_spin.value))
            )
            vector2_editor.add_child(Label.new())
            vector2_editor.get_child(0).text = "X:"
            vector2_editor.add_child(x_spin)
            vector2_editor.add_child(Label.new())
            vector2_editor.get_child(2).text = "Y:"
            vector2_editor.add_child(y_spin)
            return vector2_editor

        _:
            var label = Label.new()
            label.text = str(current_node.get(property_name))
            return label
```

```gdscript
extends Node

func save_learning_progress(data: Dictionary) -> void:
    if OS.has_feature("web"):
        # Godot 4.x では user:// が IndexedDB にマッピングされる
        var file = FileAccess.open("user://learning_progress.json", FileAccess.WRITE)
        if file:
            file.store_string(JSON.stringify(data))
            file.close()
            print("Progress saved to IndexedDB")

func load_learning_progress() -> Dictionary:
    if OS.has_feature("web"):
        if FileAccess.file_exists("user://learning_progress.json"):
            var file = FileAccess.open("user://learning_progress.json", FileAccess.READ)
            if file:
                var json_string = file.get_as_text()
                file.close()
                var json = JSON.new()
                var error = json.parse(json_string)
                if error == OK:
                    return json.data
    return {}
```

### パフォーマンス最適化

1. **メッセージバッファリング**
   - 頻繁な小さいメッセージをバッチ化
   - 変更検出による差分送信

```gdscript
var message_batch: Array = []
var batch_timer: float = 0.0
const BATCH_INTERVAL: float = 0.016  # 60FPS

func _process(delta: float) -> void:
    batch_timer += delta
    if batch_timer >= BATCH_INTERVAL and message_batch.size() > 0:
        _flush_message_batch()
        batch_timer = 0.0

func send_command_batched(command: String, params: Dictionary) -> void:
    message_batch.append({"command": command, "params": params})

func _flush_message_batch() -> void:
    if message_batch.is_empty():
        return

    var batch_message = {
        "type": "batch",
        "messages": message_batch
    }
    _send_packet(batch_message)
    message_batch.clear()
```

2. **状態同期の最適化**
   - 変更されたプロパティのみ送信
   - プロパティ更新の優先度設定

### エラーハンドリング

1. **プロセスクラッシュ検出**

```gdscript
func _check_process_alive() -> bool:
    if background_engine_pid <= 0:
        return false

    # プロセスが生きているか確認（プラットフォーム依存）
    # Linuxの場合: /proc/{pid}/存在確認
    # WindowsとmacOS: OS APIを使用
    return OS.is_process_running(background_engine_pid)

func _on_process_check_timeout() -> void:
    if not _check_process_alive():
        push_error("Background engine crashed!")
        _handle_crash()

func _handle_crash() -> void:
    # クラッシュログを収集
    # UIに通知
    # 必要に応じて再起動
    emit_signal("background_engine_crashed")
```

2. **通信タイムアウト**

```gdscript
var pending_commands: Dictionary = {}
var command_id_counter: int = 0
const COMMAND_TIMEOUT: float = 5.0

func send_command_with_callback(command: String, params: Dictionary, callback: Callable) -> void:
    var cmd_id = command_id_counter
    command_id_counter += 1

    pending_commands[cmd_id] = {
        "callback": callback,
        "timestamp": Time.get_unix_time_from_system(),
        "command": command
    }

    params["_cmd_id"] = cmd_id
    send_command(command, params)

func _check_command_timeouts() -> void:
    var current_time = Time.get_unix_time_from_system()
    var timed_out = []

    for cmd_id in pending_commands:
        var cmd_data = pending_commands[cmd_id]
        if current_time - cmd_data.timestamp > COMMAND_TIMEOUT:
            timed_out.append(cmd_id)
            push_error("Command timed out: " + cmd_data.command)

    for cmd_id in timed_out:
        pending_commands.erase(cmd_id)
```

## まとめ

本計画書では、**プラットフォームに応じた2つの実装アプローチ**を提案します。

### デスクトップ版（Windows/macOS/Linux）

**アプローチ1: ヘッドレスモード別プロセス実行**を推奨します。

**利点:**
1. **完全な分離**: メインゲームと学習対象エンジンが独立して動作
2. **柔軟性**: 既存のデバッガプロトコルを活用した通信
3. **安定性**: 一方のクラッシュが他方に影響しない
4. **拡張性**: 将来的に複数の学習対象エンジンを同時実行可能

Godotのソースコードに実装されているエディタのゲームプレビュー機能（[editor/run/editor_run.cpp](editor/run/editor_run.cpp)）を参考にすることで、堅牢な教育ゲームシステムを構築できます。

### Web/モバイル版

**アプローチ2: SubViewportによる埋め込み実行**を推奨します。

**利点:**
1. **クロスプラットフォーム**: Web、Android、iOSで動作
2. **シンプル**: プロセス間通信が不要で実装が簡単
3. **軽量**: 単一プロセスでリソース効率が良い
4. **直接アクセス**: ノードへの直接参照で高速

**制限事項:**
- ❌ **Web**: プロセス起動機能が利用不可（[platform/web/os_web.cpp:116-125](platform/web/os_web.cpp#L116-L125)）
- ❌ **Nintendo Switch**: Godotが正式サポートしていない（プラットフォーム実装なし）
- ⚠️ **グローバル状態**: シングルトンやグループの命名規則に注意が必要

### Nintendo Switch について

現時点でGodot Engineは**Nintendo Switchを正式にサポートしていません**。コードベースにプラットフォーム専用の実装が存在しないため、以下の選択肢があります：

1. **Godotへの独自プラットフォーム実装の追加**（高難度）
   - NintendoSDKとの統合
   - DisplayServer、OSレイヤーの実装
   - 開発期間: 数ヶ月〜

2. **サードパーティソリューションの利用**
   - 一部の移植会社がNintendo Switch対応サービスを提供

3. **代替エンジンの検討**
   - Unity（公式Switch対応）
   - Unreal Engine（公式Switch対応）

### 推奨する開発フロー

1. **プロトタイプ**: Web版（アプローチ2）で迅速に検証
2. **デスクトップ版**: 本格実装（アプローチ1）で完全版を開発
3. **クロスプラットフォーム**: 必要に応じてWeb/モバイルにも展開

この戦略により、最小限の工数で最大限のプラットフォームカバレッジを実現できます。
